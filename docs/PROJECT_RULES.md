# Project rules

- Follow **RESEARCH → VERIFY → PLAN → IMPLEMENT → BUILD → RUN → DEBUG → RESEARCH AGAIN**.
- Research before major implementation decisions; inspect existing code and Git history before proposing rewrites.
- Preserve working components and avoid unnecessary architecture rewrites.
- Never claim success without reproducible evidence. A process starting is not a guest boot.
- Keep proprietary Sony PUPs, keys, decrypted binaries, console dumps, images, and secrets out of GitHub.
- Do not fabricate firmware or use random third-party proprietary dumps.
- Do not present a fake/demo interface as Sony's PS4 system or Home UI.
- Do not add placeholders that imply unfinished functionality is complete.
- Do not implement SceSysCore/SceShellCore/Shell UI/Home before M0 is reproducibly verified.
- Do not use AI branding in product surfaces or AI-themed commit messages.
- Write human-readable, evidence-linked documentation and record failures as well as successes.
- Prefer reproducible, robust native Windows execution over temporary hacks; document every compatibility workaround.
- Keep logs useful for diagnosis; avoid unnecessary console spam in eventual product operation.
- Preserve useful historical evidence instead of deleting it to make the repository appear cleaner.
- Before committing, inspect the staged diff and scan for proprietary files.
